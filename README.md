# NovelHelper

本地优先的 AI 小说创作工具。设定、记忆、模式和对话历史全部保存在本机；服务只监听 `127.0.0.1`，API Key 不会离开这台电脑。

## 主要功能

- **多作品隔离**：人物、势力、物品、地图、记忆与稿件按小说分库保存，互不干扰。
- **AI 工作站**：按「写稿模式」连续对话，结果边生成边逐字出现；模型与推理强度就在「开始生成」左边一起选，生成时自动携带最近轮次与所选设定。
- **稿件处理**：左侧正文、右侧 AI 对话。让 AI 直接改写选中的段落或全文，改动在正文里标出，保留或回滚由你决定；不写入工作站的对话历史。
- **润色修订 Agent**：一句话许愿就能改稿——自动生成需求卡与改稿计划，先改一段样例确认方向，再批量局部改写并分层审核；按段落 ID 与原文哈希合并，越界返回直接丢弃；默认 3 轮内收敛、最多 5 轮，可随时保留、换一版、回滚或继续提要求。
- **模式可定制**：写稿与稿件处理各自一套模式，每个模式有固定的系统提示词与默认参数；本次用哪个模型、多强的推理，在生成前临时选。
- **接口自由**：支持 DeepSeek、OpenAI、OpenRouter、SiliconFlow、Moonshot/Kimi、阿里云百炼、智谱 GLM，以及任意 OpenAI 兼容接口。
- **开箱即用**：提供免安装的 Windows 单文件 EXE，不需要 Python 环境。

## 快速开始

- 不想装 Python：从 [最新版本](https://github.com/DreamInsight24/Novel-Helper/releases/latest) 下载 `NovelHelper.exe`，放进可写目录后双击运行，详见[下载即用版](#下载即用版windows-exe)。
- 想改代码：安装 Python 3.10 或更高版本，执行 `python -m pip install -r app\requirements.txt`，再执行 `python app\run.py`，详见[从源码运行](#从源码运行)。

## 下载即用版（Windows EXE）

不想安装 Python，可以直接使用 GitHub Releases 中的 `NovelHelper.exe`：

1. 打开 [最新版本](https://github.com/DreamInsight24/Novel-Helper/releases/latest)，下载 `NovelHelper.exe`。
2. 把 EXE 放进一个有写入权限的文件夹，例如 `D:\NovelHelper\`，再双击运行。
3. 应用会直接打开 NovelHelper 窗口，不再自动打开浏览器；端口由系统自动分配。启动时先显示约 1.2 秒的开屏页，关闭窗口即停止服务。
4. 窗口每次启动都会在主屏工作区内居中，并按屏幕大小自动收缩，不会出现在右下角或超出屏幕；最大化后关闭再打开，也会恢复默认的大小和位置。
5. EXE 是窗口程序，双击不会弹出控制台或命令行窗口；启动失败时会用原生对话框提示并写入 `log/`。
6. EXE、窗口标题栏和网页图标使用统一的 NovelHelper 图标。
7. Windows 10/11 需要 [Microsoft Edge WebView2 Runtime](https://go.microsoft.com/fwlink/p/?LinkId=2124703)。Windows 11 和较新的 Windows 10 通常已内置；缺失时程序会给出安装提示，不会静默改用浏览器。

EXE 是单文件便携版，不需要安装。首次启动会在 EXE 旁边创建 `data/`、`workspace/` 和 `log/`，升级时只需替换 EXE。请保留这三个目录，否则设定、对话历史和导出文件不会保留。

> 程序尚未进行代码签名，Windows SmartScreen 可能提示“未知发布者”。确认文件来自本仓库的 Releases 后，可选择“更多信息 → 仍要运行”。

如果 EXE 所在目录不可写，可以设置环境变量 `NOVELHELPER_HOME` 指向可写目录：

```powershell
$env:NOVELHELPER_HOME = "D:\NovelHelperData"
.\NovelHelper.exe
```

可以随时检查安装是否完整、数据目录是否可写：

```powershell
.\NovelHelper.exe --check
```

## 从源码运行

### Windows

1. 安装 Python 3.10 或更高版本。
2. 在仓库根目录安装依赖并启动：

   ```powershell
   python -m pip install -r app\requirements.txt
   python app\run.py
   ```

3. 按首次引导选择接口、填写 API Key 并选择模型。可以跳过，稍后在「模型设置」中配置。

仓库不提供 `.bat` 启动脚本；源码运行统一使用 `python app\run.py`，需要固定端口或只启动服务时在命令后加参数。

### 命令行启动

```bash
python app/run.py                  # 打开桌面窗口
python app/run.py --port 9000      # 本次使用固定端口
python app/run.py --no-window      # 只启动本地服务（源码运行时在控制台查看地址）
```

不使用 `--port` 时，程序会读取全局配置 `app/data/config.json` 的端口设置。默认使用 `port_mode=auto`，由系统分配空闲端口；固定端口冲突会直接报错退出，不会自动换端口，也不会打开浏览器。`--no-browser` 仍可用，但已弃用，等同 `--no-window`。

## 首次引导

第一次打开会进入两步引导：

1. 选择语言：可选列表，点击即时预览；部分初始化预设（元素模板、自定义栏目、记忆分类、默认模式名与说明、默认记录名、世界地图行列名等）会按这里选择的语言生成并保存，之后切换语言不会改写。
2. 接口设置：选择提供商预设，或填写自定义 OpenAI 兼容 URL；填写 API Key；获取或手动填写模型；选择默认模型和默认推理强度。

两步之间可以返回上一步。接口设置可以跳过，稍后在「模型设置 → 设置向导」重新打开。

## 日常使用

### 模型设置

- 选择 DeepSeek、OpenAI、OpenRouter、SiliconFlow、Moonshot/Kimi、阿里云百炼、智谱 GLM 或自定义接口。
- URL 和 API Key 都可以手动填写；自定义或本地接口允许不填 Key。
- 「从接口获取可用模型」会读取当前 URL 的 `/models`；也可以手动维护模型列表。
- DeepSeek 预设当前提供 `deepseek-flash` 与 `deepseek-v4-pro`。
- 设置默认模型、默认推理强度和超时。
- **端口**：在首页「全局设置 → 应用」选择自动分配或固定端口，保存后下次启动生效；小说设置页只读展示。命令行 `--port` 可临时覆盖。
- 「测试连接」只发送一条很短的测试请求，不会写入对话历史。

### 模式管理

模式分成两类，分别给两个工作界面使用：

- **写稿模式**：只出现在「AI 工作站」，用于从设定和提示词生成新内容；
- **稿件处理模式**：只出现在「稿件处理」页，用于处理已有稿件（默认有「润色修订」）。

两类模式在「模式管理」页用页签分开，互不混淆。每个模式都是一套独立的系统提示词，并带有自己的默认参数：

- 在当前页签新增模式；
- 在模式顶部设置默认推理强度、`max_tokens`、`top_p`、`temperature`、`thinking`；模型不在这里指定，统一在生成前选择；
- 编辑「用途」可以把模式移到另一组；
- 编辑该模式的系统提示词；
- 切换接口后，模式的可用模型来自「模型设置」里的清单。

### AI 工作站

只使用**写稿模式**，采用连续对话布局：

- 左侧「返回作品库」下方的「对话」可展开或收起历史，右侧「+」新建对话；当前对话为空时复用它。点击历史直接继续写作，每条历史的「⋯」打开就近的小菜单，可重命名或删除，删除需再次确认。
- 中央按轮次展示用户要求与 AI 正文，结果边生成边逐字出现；每条结果分别支持复制、另存为 TXT/MD、追加到当前稿件、追加到提示词和查看原文，长正文可以收起。完整写作产出的新章节带「前往稿件处理」，点一下直接打开那一章。
- 底部输入本次写作要求，直接选择写稿模式与目标字数；输入栏右侧紧挨「开始生成」的是模型与推理强度菜单（和 Agent 类工具一样，先选模型再选推理强度），没有单独指定的项跟随模式默认值。「设定与要求」打开右侧抽屉，默认显示侧栏设定，可从「更多设定」添加其他栏目，再在下方选择具体条目；「补充要求」统一填写，旧内容自动合并。
- 每段对话保留未发送草稿；生成成功后清空本次提示词，失败保留输入并可重试。支持 Ctrl+Enter 发送。
- 续写按时间顺序携带最近最多 8 个完整轮次，历史合计不超过 60,000 字符，超出预算时从最旧轮次起舍弃；本次设定按当前选择重新拼装。「预览将发送的内容」可查看历史消息及当前提示词。
- 生成期间只有「开始生成」换成「停止生成」，模式、模型、设定和历史照常可用，切到别的页面也能看到侧栏的生成指示；点「停止生成」后这次结果不写入历史。

### 设定与导入

- 设定条目集中在编辑面板顶部的横向滚动栏，支持滚轮、左右方向键和 Home/End 切换，搜索、分类、标签筛选及“其他设定”的多选搬运仍可使用。人物背包的角色选择、地图的区域选择也采用顶部横栏。
- 内容中的信息分组（如“身份”“外貌”）可通过左侧拖动柄排序，或聚焦拖动柄后按 Alt + 上/下方向键；右侧按钮可删除当前条目的分组。删除后可“恢复上一个”或“恢复全部”，恢复保留字段值、嵌套结构和原位置；在本栏目内切换条目或内容/关联/更多页签仍可恢复。离开栏目、切换小说或刷新后结束临时恢复，删除和排序按自动保存机制保留，栏目模板不受影响。

- 点击“新建”直接创建并选中条目，可立即改名；新条目套用本栏目的完整元素模板，修改不会影响其它条目或模板。
- 编辑页分为「内容 / 关联 / 更多」：分类、标签 chip、备注和模板信息在内容页；正文保留为“其他 / 补充描述”。更多页保留来源、编辑结构、搬运和删除。物品标签支持筛选及跨本栏目条目重命名/删除；分类管理位于页头，删除分类后条目保留为未分类。
- 人物所属势力和势力成员使用同一份关联，支持搜索选择、就地新建、身份说明和双向跳转。旧的文字关系保留，不按名称自动转换；其他条目关系仍可通过正文或原字段描述。
- 元信息（原元素模板）迁至「设定管理 → 对应栏目 → 编辑」，与栏目名称、说明一起维护。支持字段分组、增删、层级、排序、启停、导出模板 JSON，以及确认后向已有条目补充缺失字段；不覆盖已填值。
- JSON 导入统一位于「设定管理 → 导入设定」，先选择目标栏目，再从导入目录选择文件或选择本地文件。地图与记忆 JSON 也在此导入。
- Markdown / TXT（扩展名不区分大小写）可从本地选择或当前小说导入目录导入到“其他设定”；没有小节标题时整体导入，空文件不生成条目。AI 设定生成对话框打开时刷新文件列表，空状态只保留右上角新建提示。
- 地图 JSON 必须包含 `rows`、`cols`、`cells`、`regions`。同名条目按现有规则合并更新；格式与操作说明位于「?」帮助中。
- 新正文、概述与人物势力关联会进入 AI 上下文；旧元素字段和备注继续保留，导入导出支持新正文与概述。

- 新小说默认只显示人物档案、人物背包、世界、地图、势力、物品及其他设定；七个扩展栏目在设定管理中可单独开启。每个栏目的隐藏互不影响，旧小说布局迁移保持原行为。
- 新文件由服务端解析当前小说工作区，导入前自动生成导出目录下的 `backup_<时间戳>/` 集合快照；失败时回滚。默认导出同名文件自动编号，指定外部路径的覆盖需确认，覆盖前保留最近一版 `.bak`。导入导出 JSON 结构保持兼容。
- AI 工作站可为本次请求选择模型与推理强度，默认跟随模式；目标字数可选“限定/不限”，不限时不发送目标字数。长说明已从输入区移除。

### 关系网

- 小说内「设定」分组底部提供「关系网」，展示本小说全部条目（含未关联条目）与关联，支持栏目筛选、搜索、缩放、拖动平移与重置。
- 设定内「关联」页只显示当前条目及直接关联的一层放射图，保留直接关联列表；完整网络从「打开关系网」进入。
- 关联选择器支持搜索、栏目筛选、预设或自定义关系名称、方向和备注，也可输入名称后套用目标栏目模板新建条目。保存前先落盘待保存条目，避免刚新建的条目无法关联。
- 图中双击另一个条目会进入其关联页；记忆与地图区域打开关联详情。关系网支持选择节点后新建、编辑、解除关联，也可点击连线编辑；解除关联保留条目。
- 无效关联会被丢弃并提示，其余关联正常保存；保存前在小说数据目录的 `relation_backups/` 写快照，失败时恢复关系与势力成员投影。
- AI 拼装时，每个选中条目在自己的内容块末尾列出全部关联，包括未选对端的名称、方向、类型和备注，不展开对端正文；不再输出独立的全局关联区块。

### 全局角色卡

- 首页作品库下方提供独立角色卡，即使没有小说也可使用；支持姓名、性别、身份、年龄、标签、简介、备注的编辑、搜索和排序。
- 纵向卡片的上 3/5 显示图片，下 2/5 显示基本信息；点击后在右侧查看并编辑，Esc 关闭详情，删除前确认且默认焦点在取消。
- 数据固定写入 `app/data/cards.json`，图片位于全局 `app/data/card_images/`，卡片只保存图片文件名；支持 PNG/JPEG/WebP，单张最多 2 MB，无图或图片缺失时显示内置默认图。
- 角色卡不随小说切换或删除，不参与小说 AI 上下文，也不与小说人物档案隐式同步。编辑前快照保存在 `app/data/card_backups/`；删除角色卡后保留图片以便恢复快照。

### 稿件处理

稿件处理属于**当前小说**，与 AI 工作站中的对话无关。每本小说分别保存正文草稿、修订会话和绑定文件。

- 布局是「左正文、右 Agent」：右侧面板像集成在编辑器里的润色修订 Agent 一样工作，打开后直接显示当前修订会话。
- 顶部的章节栏列出本小说已有的章节，可收起；完整写作产出的新章节自动出现在这里，点「来自对话」回到生成它的那次会话。
- 「文本处理工具」集中提供文本清理和查找替换；有选区时默认只处理选区，否则处理全文。编辑、清理和替换可撤销、重做。
- 工具栏提供 AI 辅助、撤销/重做、保存、导出 TXT 和「导入至章节」；章节保存正文原文，同名文件自动编号。正文自动暂存；绑定到文件后停手 1.5 秒自动写盘，离开页面时保存。
- AI 辅助就是润色修订 Agent，不再区分「快速改写」与「修订 Agent」：在输入框里说清要改什么即可，有选区时默认改选区，没有选区时默认改当前章。
- Agent 会先给出需求卡与改稿计划，再改一段样例让你确认方向；确认后批量改写，改动以绿色高亮落在正文上，正文暂时只读。审核不通过会自动定向重改，直到收敛或到达轮次上限。
- 最终版本由你决定「保留这版 / 换一版 / 回滚」；保留会记一个撤销点。未确认前不能再次发起修订，刷新页面后修订会话和未确认的 diff 都还在。
- 面板里的模型与推理强度和 AI 工作站共用同一套菜单，改完下一次请求就生效；停止生成后正文不动。稿件处理不会写入 AI 工作站的对话历史。
- AI 工作站里生成的结果用「追加到当前稿件」直接接到正文末尾；绑定文件时会照常自动保存。

### 润色修订 Agent

AI 辅助只有这一种模式：按「许愿 → 需求卡 → 样例 → 批量 → 审核 → 确认」推进，适合不想逐条描述修改要求的场景。

- **许愿式输入**：直接说「把这一章开头改得紧张一点」即可。系统自动生成一句话需求卡（范围、目标、风格、保留项、禁止项）；需求太模糊时最多追问 1 个带选项的问题，不要求填空。有选区时默认改选区，没有选区时默认改当前章。
- **样例先行**：先只改 1 个代表性段落并展示 diff；点「行，按这个继续」再批量执行，也可以「再口语点」「换方向」或跳过样例。
- **段落协议**：每个自然段都有 `paragraph_id` 与原文哈希；**一个换行符就是一段**，空行只作为排版空白保留，不要求 Markdown 式的额外空行。第二轮只接收目标段的结构化修订；模型返回全文、非目标段或越界内容时丢弃并告警，哈希对不上时拒绝合并。漏段、空返回或 JSON 失败会重试一次，仍失败则标记待人工，不阻塞其他段。
- **分层审核**：局部（是否满足方向）、一致性（人物、称呼、设定、时间线、衔接）、全局（整体文风与需求达成度，短篇或明确要求时启用）三层审核，输出结构化问题清单与 `next_instruction`，自动驱动下一轮只改问题段。
- **轮次与收敛**：默认软上限 3 轮、硬上限 5 轮；连续两轮问题不变、diff 极小或出现 A→B→A 震荡时停止，并给出「接受当前版本 / 换改写策略 / 保留问题清单」三个出口。第 5 轮不再自动继续。
- **确认与回滚**：审核通过后展示完整 diff，由你决定「保留这版 / 换一版 / 回滚到上一版 / 按段回滚 / 继续提要求」。刷新页面或重启后会话仍在，可继续确认。说「直接改，不用确认」会跳过样例与逐步确认，但仍保留最终 diff 和回滚。
- **上下文控制**：中短篇首次改写可带全文，之后只用稳定摘要（只追加、不重写）+ 目标段前后文 + 全局约束；长篇不发送全文。
- **配置**：`config.revision` 可调 `sample_first`、`soft_rounds`、`hard_rounds`（1–5）、`global_review`（`auto` / `always` / `off`）、`full_text_limit`、`max_targets` 等。修订会话按小说保存在 `data/novels/<id>/revisions/`，包含每轮 diff、问题清单、候选版本与回滚快照。

```text
app/
├── data/
│   ├── config.json       全局配置与活动小说 ID
│   └── novels/           各小说设定、模式、历史、配置与会话

│   └── novels/           各小说隔离的导入、导出、正文与稿件工作区
└── ...
log/

```

从 EXE 运行时，目录与 EXE 同级：

```text
NovelHelper.exe
├── data/
│   ├── config.json       全局配置与活动小说 ID
│   └── novels/           每本小说独立的数据、配置与会话
├── workspace/
│   └── novels/           每本小说隔离的导入、导出、正文与稿件处理工作区
└── log/                  操作、AI 交互与错误日志
```

PyInstaller 的程序文件会解包到系统临时目录，但数据不会写入临时目录，因此每次启动都能继续使用同一份设定。可用 `NOVELHELPER_HOME` 改变整个运行目录，或用 `NOVELHELPER_DATA` 只改变数据目录。

每次启动会新建 `log/novelhelper_YYYYMMDD_HHMMSS.log`，最多保留 10 个日志文件，超出时自动删除最早的。API Key 不会写入日志。

对话历史只保存设定条目的 ID 指针，不重复保存整份设定；失效指针在读取时自动跳过。

## 打包 Windows EXE

本项目只保留一种 EXE 打包方式：[PyInstaller](https://pyinstaller.org/) 单文件构建，配置为 `NovelHelper.spec`。它会把 Python、`openai`、`pywebview`/pythonnet 依赖、图标、开屏页和网页资源一起打进单个 `NovelHelper.exe`。EXE 使用窗口子系统（`console=False`），双击不会弹出控制台；仓库不提供 `.bat` 启动脚本，也不维护其他打包器配置。

### 本地打包

要求 Windows 10/11 x64 和 Python 3.10 或更高版本，并在仓库根目录执行。Windows EXE 必须在 Windows 上构建，不能用 Linux/macOS 交叉打包。

建议使用干净的虚拟环境，避免构建机上的无关包触发 PyInstaller hook：

```powershell
# 1. 创建虚拟环境并安装运行、构建依赖
python -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -r app\requirements.txt -r requirements-build.txt

# 2. 构建单文件 EXE
.venv\Scripts\python.exe -m PyInstaller --clean --noconfirm NovelHelper.spec

# 3. 验证构建结果
.\dist\NovelHelper.exe --check
.venv\Scripts\python.exe scripts\exe_smoke_test.py .\dist\NovelHelper.exe
```

构建结果位于 `dist\NovelHelper.exe`，可直接复制到其他 Windows 电脑运行。`build/`、`dist/` 已加入 `.gitignore`，不会提交到仓库。

建议再手动启动一次窗口，确认开屏页至少显示约 1 秒、窗口居中且不超出屏幕、图标正常、首页加载、WebView2 可用，以及关闭窗口后进程退出：

```powershell
.\dist\NovelHelper.exe
```

`--check` 和 `exe_smoke_test.py` 会检查打包资源、版本、服务模式以及配置和历史的持久化；冒烟测试使用临时目录，不会修改真实数据。WebView2 缺失时程序会提示安装运行时，不会退回浏览器。

EXE 是窗口程序，PowerShell 直接运行 `--check` 时可能不等待进程结束；需要等待并取得退出码时使用：

```powershell
$check = Start-Process .\dist\NovelHelper.exe -ArgumentList '--check' -Wait -NoNewWindow -PassThru
$check.ExitCode
```

如果构建时出现无关第三方包的 hook 报错，删除 `.venv` 后按上面的步骤重建干净环境；如果 `dist` 中的 EXE 正在运行，先关闭再重新构建。

如果运行时报 `Could not create temporary directory!`，说明 EXE 所在目录的 ACL 不允许 PyInstaller 创建临时解包目录；把 EXE 复制到普通可写目录（如 `D:\Temp`）后重试即可，构建本身没有问题。

如果运行时弹出“无法加载 pywebview 桌面组件。请重新安装依赖（pip install -r app/requirements.txt）”，说明构建时所用的 Python 没有安装 pywebview，EXE 里根本没有桌面组件。这与把 EXE 复制到哪个目录无关：单文件 EXE 的依赖在临时解包目录里，位置不影响导入。请确认 `pyinstaller` 来自 `.venv`（`where.exe pyinstaller` 应指向 `.venv\Scripts\`，而不是全局 Python），然后用 `.venv\Scripts\python.exe -m PyInstaller --clean --noconfirm NovelHelper.spec` 重新构建。现在 spec 会在缺少 pywebview/pythonnet 时直接中止构建并提示，不再静默产出坏 EXE。

### GitHub Actions 自动构建

`.github/workflows/build-windows.yml` 会在以下时机自动构建：

- 手动触发 `workflow_dispatch`；
- 修改 `app/`、`scripts/`、spec 或工作流文件的 Pull Request（仅生成构建产物）；
- 推送形如 `v*` 的标签时，自动创建 GitHub Release 并附上 EXE 与 SHA-256 校验文件。

本地可用 `python scripts/exe_smoke_test.py dist\NovelHelper.exe` 执行 EXE 隔离冒烟（`--check`、版本、服务模式、配置持久化与重启）。

发布新版本：

```bash
git tag -a v2611.1 -m "v2611.1"
git push origin v2611.1
```

工作流会先检查 tag 与应用版本 `novelhelper._version.APP_VERSION` 是否一致（不一致直接失败），再运行桌面/端口测试、自检和 EXE `--check`/`--no-window` 冒烟；通过后才上传产物并创建 Release。

构建完成后可在 Actions 的 `Artifacts` 下载 `NovelHelper-windows-x64`，或在 Releases 中直接下载 `NovelHelper.exe`。
