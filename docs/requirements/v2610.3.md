## 1. 背景与目标

Novel-Helper 目前以“单本小说 + 浏览器页面”为中心：所有设定、模式、历史和工作区文件共用一套数据目录；设定编辑以长文本和密集表单为主；用户只能手工整理零散设定；启动时依赖固定端口并自动打开浏览器。v2610.3 面向“作品库 + 桌面应用”做一次结构性升级。

本版本目标：

1. **多小说与图形化首页**：提供可创建、选择、切换、重命名和删除小说的首页，并保证每本小说的数据、历史、配置和工作区完全隔离；首次启动时初始化空作品库。本项目尚未投入使用，不处理旧版单本数据迁移。
2. **设定界面视觉化**：在不改变数据格式的前提下，用卡片、分组、进度、标签、折叠和按需展开等方式替代大段文字堆叠，重点改善设定总览与设定编辑体验。
3. **AI 设定生成**：在任意记录型设定页提供统一入口，读取用户粘贴或导入的非结构化文本，由 AI 抽取为结构化 JSON，再由程序确定性映射到元素树并自动加入对应设定；提示词对用户隐藏且不可修改，并尽量降低 token 消耗。
4. **桌面化与动态端口**：使用 pywebview 承载应用窗口，不再自动打开浏览器；未指定端口时向系统申请空闲端口，显式指定端口被占用时明确提示并终止，不静默回退。

**非目标**：

- 不引入账号、云同步、多人协作或在线发布；
- 不替换现有编辑器技术栈，不引入重型前端框架；
- 不改变现有 JSON 集合中记录、元素树、模式、历史的基本字段语义；
- 不提供 AI 提示词编辑、提示词市场或用户自定义系统提示词；
- 不要求隐藏控制台窗口，不要求实现自动更新；
- 不重做移动端布局；本版本以桌面 1024px 以上宽度为验收基线；
- 不要求 AI 生成世界地图网格或记忆条目，这两类页面有独立数据结构，留待后续版本。

## 3. 通用要求

### 3.1 分支、提交与 PR

- 每个任务从 `dev/v2610.3` 拉出上表对应分支，PR 目标分支为 `dev/v2610.3`；
- 合并策略沿用仓库约定：squash merge；
- PR 必须包含变更说明、影响范围、自测清单、文档链接和 UI 截图/录屏；
- 任务 1、任务 2 的 UI 方案和任务 4 的启动行为需负责人 review 通过后才能合并；
- 不得在任务分支中顺带重构无关模块。

### 3.2 完成定义（DoD）

代码合并 + 文档更新 + 自动化测试/冒烟通过 + 必要的手工验收 + 打包验证（涉及资源或启动方式时）+ review 通过 + 验收标准逐条勾选。

### 3.3 国际化与文案

- 新增界面文案必须同时提供 `zh-CN` 与 `en-US`，key 集合一致，使用整句 key 与占位符；
- HTML 静态文案使用 `data-i18n`，JS 动态文案使用 `t()`；动态插入 DOM 后调用 `i18n.apply()`；
- AI 系统提示词、模型指令、日志和异常堆栈不进入翻译表，也不在界面展示；
- 用户数据（小说名、设定名、字段值）不翻译。

### 3.4 数据安全与兼容

- 首次启动初始化和新建小说必须可重复执行且不覆盖已有数据；本版本不处理旧版用户数据迁移；
- 初始化失败时保留已有数据并给出可读错误，不得静默覆盖；
- 不得跨小说读取或写入设定、模式、历史、稿件、导入导出文件；
- 不改变现有集合的 JSON 字段语义；新增字段必须可选，旧数据缺少时按默认值处理。

### 3.5 测试基线

每个任务合并前至少执行：

```powershell
python -X utf8 -B scripts/smoke_test.py
python -X utf8 -B app/selftest.py
python -X utf8 -B scripts/check_dependencies.py
node --check app/novelhelper/web/core.js
git diff --check
```

涉及新功能时补充对应单元测试或集成测试；涉及资源、pywebview 或打包时补充 EXE 冒烟。

## 4. 任务 1：多小说数据层与图形化首页

### 4.1 目标

把“当前只有一本小说”的隐式假设改为显式的“作品库”。用户启动后先看到首页，可以选择已有小说进入，也可以新建小说；每本小说拥有独立的设定、模式、历史、小说级配置、状态和工作区。本项目仍处于开发阶段且没有旧版用户数据，首次启动只初始化新布局，不实现旧版单本数据迁移。

### 4.2 功能范围

1. **首页入口**
   - 应用启动后默认进入首页，而不是直接进入上次的编辑页；
   - 首页为顶层页，包含作品库与全局设置；品牌名与“作品库”均可返回首页；
   - 打开小说后进入该小说工作区，左侧导航切换为小说内页面，并提供“返回作品库”入口；
   - 首页显示当前活动小说状态；有进行中的生成任务时给出提示。
2. **小说卡片/列表**
   - 至少展示：标题、作者（可选）、最后编辑/打开时间、当前活动标识；
   - 可展示设定条目数、记忆数、总字数等摘要；摘要读取失败不得影响首页整体渲染；
   - 布局由成员设计，卡片网格、书架或列表均可，但必须有清晰的“打开/继续写作”主操作。
3. **新建小说**
   - 必填标题；可选作者、简介；
   - 新建时按当前界面语言生成该小说的内置预设（元素模板、自定义栏目、模式、记忆分类、世界地图坐标等），不得复用另一本小说的用户数据；
   - 创建成功后直接进入该小说，或停留在首页并高亮新小说；两种方式择一，但必须一致。
4. **切换小说**
   - 打开另一本小说前，先等待当前页面的防抖保存完成；切换后所有集合、历史、工作区路径、侧栏计数必须指向新小说；
   - 切换请求期间禁用重复点击，显示加载状态；
   - 活动小说 ID 持久化到全局配置，重启后保留；启动仍先到首页，不自动进入。
5. **重命名与删除**
   - 重命名修改标题/作者/简介，不改变小说 ID 和数据目录；
   - 删除必须二次确认，正常条目的确认文案包含小说标题，损坏元数据时包含小说 ID；活动小说删除后回到首页或切换到剩余小说；
   - 删除前必须确保没有未完成的生成任务。确认后将小说数据目录和工作区移入操作系统回收站；回收站不可用或操作失败时保留数据并提示失败，不得静默永久删除。
6. **搜索、排序与状态**
   - 小说数量较多时支持按标题/作者搜索，支持按最后编辑或创建时间排序；
   - 必须有空状态、加载状态、读取失败状态和损坏小说条目的降级展示；
   - 所有破坏性操作有明确的取消路径。

### 4.3 数据模型与隔离

**全局数据**（跨小说共享）：API/提供商配置、服务端口、界面语言、首次引导状态、当前活动小说 ID、程序版本/初始化标记、日志。全局配置始终单独存储，不因活动小说切换而改变。

**小说级数据**（每本独立）：小说配置 `config.json`、元素模板 `schema`、自定义栏目 `sections`、模式 `modes`、状态 `state`、历史 `history`、会话 `conversations`、人物/势力/道具/装备/其他/记忆/世界地图等集合，以及导入、导出、正文、稿件处理工作区。

小说配置在创建小说时由当时的全局配置复制生成。API Key、提供商参数、端口等可配置项默认跟随全局配置，有效值取全局配置；用户可在小说设置中直接编辑本小说配置，未修改的项继续继承全局配置。小说设置页提供“恢复全局配置”按钮（与全局一致时置灰不可点），用于清除本小说的专属覆盖；全局配置的编辑入口在首页“全局设置”。新建小说不得复制其他小说的配置覆盖、设定或用户数据；配置快照仅作为该小说初始设置记录，默认跟随全局的字段仍由全局值生效。

推荐布局（允许在实现计划中调整，但必须经负责人确认并写入 `docs/architecture.md`）：

```text
data/
  config.json                    # 唯一全局配置，含 active_novel_id、language、api、server 等
  novels/
    <novel_id>/
      novel.json                 # id/title/author/description/created/updated/last_opened
      config.json                # 小说配置副本；逐字段记录是否使用全局值及小说专属覆盖值
      schema.json
      sections.json
      modes.json
      state.json
      history.json
      meta.json
      characters.json
      factions.json
      items.json
      equipment.json
      other.json
      memories.json
      worldmap.json
      conversations/
workspace/
  novels/
    <novel_id>/
      import/
      export/
      output/
      text/
```

要求：

- 小说 ID 由服务端生成，只能包含小写字母、数字、下划线或连字符；任何 HTTP 参数都不得直接拼接为文件路径；
- `novel.json` 是小说的元数据唯一来源；首页列表以扫描小说目录为准，损坏的 `novel.json` 不得导致整个首页 500；
- 工作区路径必须按小说隔离。除明确属于应用全局的配置外，配置中的工作区路径值均解释为小说工作区内的相对路径片段，并解析到 `workspace/novels/<novel_id>/` 下；拒绝绝对路径、盘符路径、UNC 路径及解析后逃出当前小说工作区的路径；
- 全局 `data/config.json` 不移动或覆盖。小说 `config.json` 是独立配置副本，保存逐项“使用全局配置”标记及小说专属覆盖值；包含 API Key 在内的配置均可选择跟随全局或使用小说值，默认跟随全局；
- 全局设置入口必须可从小说设置页进入；切换小说后有效配置按目标小说配置解析，不能修改其他小说设置；日志保持全局。
- 备份、导出、导入、稿件处理、AI 历史等现有功能都要使用当前小说上下文。

### 4.4 建议接口

具体路径可在实现时微调，但必须满足相同语义，并更新 `docs/api/server.md`。所有响应沿用现有 `{ "ok": true/false, ... }` 约定，用户可见错误走本地化错误码或后端译文。

| 方法/路径 | 作用 | 关键点 |
|---|---|---|
| `GET /api/novels` | 列出小说和当前活动 ID | 不要求先有活动小说；损坏条目降级返回 |
| `POST /api/novels` | 新建小说 | 标题必填；返回新小说元数据 |
| `POST /api/novels/open` | 切换活动小说 | 请求体 `{id}`；保存/生成冲突时返回可读错误 |
| `POST /api/novels/update` | 重命名/改作者/简介 | 请求体含 `id` 和要更新的字段；不接受任意路径 |
| `POST /api/novels/delete` | 删除小说 | 元数据正常时确认标题；损坏条目使用小说 ID 确认；活动小说删除要处理后续状态 |
| `GET /api/novels/current` | 读取当前小说 | 没有活动小说时返回空状态而非 500 |
| `GET /api/settings/config` | 读取全局、当前小说和有效配置 | 小说设置页需要同时展示小说配置和进入全局配置的入口 |
| `POST /api/settings/config` | 保存 `global` 或当前 `novel` 配置 | 小说配置按字段记录是否使用全局值；不能把小说配置误写入全局 |

现有 `/api/state` 与所有集合 API 保持路径不变，但只能读写当前活动小说。`/api/state` 应额外返回当前小说元数据，供前端显示。

### 4.5 首次启动初始化

本项目尚未投入使用，不存在需要保留的旧版单本用户数据，因此不实现旧布局检测、数据迁移、迁移备份或迁移回滚。

1. 首次启动时初始化全局数据目录、空的 `novels/` 作品库目录、全局配置和初始化标记；初始化可重复执行，不覆盖已有全局配置或小说数据；
2. 首次启动不自动创建小说，首页应显示空状态和新建入口；
3. 新建小说时生成 ID、元数据、内置预设、小说级 `config.json` 和工作区目录；配置从当时全局配置复制为小说配置初值，所有可继承项默认“使用全局配置”；
4. 初始化失败时停止继续使用未完成的存储结构，给出可读错误；不得清理或覆盖已经存在的数据。

### 4.6 交互与视觉要求

- “新建小说”是首页最醒目的主操作；空状态必须有引导文案和按钮，不能只显示空白；
- 当前小说有明确标识，但不要用仅靠颜色区分的信息；
- 删除、切换等操作要防止误触；删除对话框默认焦点在取消；
- 支持键盘操作：Tab 焦点可见，Enter 打开卡片，Esc 关闭弹窗；
- 首页在 1024×720 和 1440×900 下无横向滚动、无文字截断；中文/英文均需检查；
- 首页与后续设定界面共用同一套颜色、间距、圆角和按钮规范，不出现两套视觉语言；
- 允许成员自行设计排布，但必须提交设计稿/截图并由负责人审核。

### 4.7 验收标准

- [ ] 启动默认进入首页；无小说时显示空状态和新建入口；有小说时可打开/切换；
- [ ] 新建小说成功，内置预设按当前语言生成，且不包含其他小说的数据；
- [ ] 两本小说的人物、势力、道具、自定义栏目、模式、历史、状态和工作区互不串数据；
- [ ] 重启后当前小说 ID 保留，启动仍进入首页；
- [ ] 重命名不改变小说 ID/目录；删除有二次确认，删除活动小说后状态正确；
- [ ] 删除确认默认焦点为取消；损坏元数据条目可用小说 ID 确认删除，且不提供重命名；
- [ ] 切换前未保存内容已落盘，进行中的生成任务有提示或被拒绝，不能静默丢失；
- [ ] 首次启动初始化可重复执行且不覆盖已有配置/小说；不包含旧版单本数据迁移逻辑；
- [ ] 损坏的 `novel.json` 只影响对应条目，首页仍可用；
- [ ] 小说 ID 经过校验，不能通过 API 路径穿越到其他目录；
- [ ] 中英文界面、1024×720/1440×900 截图通过负责人审核；
- [ ] 新增自动化测试覆盖创建、切换、隔离、配置继承/覆盖、删除回收站行为和首次启动初始化；
- [ ] `docs/architecture.md`、`docs/api/server.md`、README 相关说明和 `CHANGELOG.md` 已更新。

截图与负责人验收是手工门禁，自动化测试不能代替。首页需提交中文、英文各一组 1024×720 与 1440×900 截图，并由负责人确认无横向滚动、文字截断或操作遮挡；未提交和审核前不得将该项记为通过。

### 4.8 交付物

- 多小说存储/首次启动初始化与首页 UI；
- 小说管理 API 与当前小说上下文；
- 首次启动初始化逻辑与小说配置继承/覆盖说明；
- 自动化测试与手工验收截图；
- `docs/architecture.md` 的布局/上下文说明、`docs/api/server.md` 的新接口说明；
- 首页设计说明（可由成员自行组织）。

## 5. 任务 2：设定界面视觉化与交互优化

### 5.1 目标

在不改变现有数据结构和业务能力的前提下，降低设定页面的文字密度，让用户更快看懂“有哪些设定、填了多少、还缺什么、下一步做什么”。重点是设定总览、记录列表和记录编辑器，不要求重做整个应用。

### 5.2 范围

优先覆盖：

- 人物档案、势力、道具、装备、其他设定、所有自定义栏目；
- 设定记录列表与单条记录编辑器；
- 元素模板页、自定义栏目管理页中与设定结构直接相关的部分。

可顺带统一但不强制：侧栏计数、空状态、保存状态、导入面板、按钮与表单控件样式。

**不在范围**：AI 工作站、稿件处理、模式管理的业务逻辑；后端集合格式；路由 URL；导入导出格式。

### 5.3 设计要求

1. **先总览，后细节**
   - 每个设定页首屏应能让用户看到该栏目的概况：条目数、已填写程度、最近编辑、快速新建/导入入口；
   - 记录列表用卡片或信息行呈现名称、分类/标签、完成度、更新时间，避免只显示一列名称。
2. **减少大段文字**
   - 记录编辑器按元素树的顶层分组拆成可折叠卡片/区块，默认只展开必要的组；
   - 长文本字段默认显示摘要或较少行数，提供“展开编辑/全屏编辑/预览”，不要把多个大 textarea 同时铺满页面；
   - 使用标签 chip、状态徽标、进度环/进度条、分组图标等表达结构和完成度；
   - 对短值、枚举、备注、标签等使用更合适的控件，而不是一律 textarea。
3. **渐进披露**
   - 高级/低频字段收进折叠区或“更多”；
   - 保留现有“文档/树”高级编辑模式作为回退入口，熟练用户仍可直接编辑结构；
   - 切换模式不得丢数据。
4. **关系与可读性**
   - 人物-势力成员、背包、装备等指针关系用可读的名称 chip/列表呈现，坏指针继续有降级提示；
   - 不强行按字段名猜测数据类型；如做类型推断，必须可回退、不得改写值、不得依赖某一种语言。
5. **状态与反馈**
   - 保存中/已保存/保存失败状态清晰可见；
   - 空栏目、无搜索结果、加载失败都有明确下一步；
   - 批量操作、删除等危险操作保持确认。
6. **可访问性与国际化**
   - 键盘可完成主要操作，焦点可见；
   - 文本与背景对比度满足基本可读性；
   - 所有新增文案中英对齐；英文变长不得造成按钮错位或文字截断；
   - 1024×720 与 1440×900 下无横向滚动。

### 5.4 约束

- 不新增前端框架或大型依赖，继续使用现有 `h()`、`renderMain()` 和 CSS；
- 不改变集合 JSON 字段名、元素树结构、记录 ID、导入导出格式；
- 不改变现有业务 URL 和保存防抖策略；如调整保存逻辑，必须补充回归测试；
- 不为了视觉效果删除现有功能；高级模式、导入、导出、搬运、搜索、批量选择都要保留；
- 组件应可复用，避免每个页面复制一套卡片/折叠逻辑；
- 性能可接受：单栏目 200 条记录时列表滚动和搜索不明显卡顿。

### 5.5 工作方式

1. 先提交设计提案：页面结构、组件清单、关键交互、颜色/间距/图标规范、改前改后示意图；

## 6. 任务 3：AI 设定生成

### 6.1 目标

用户可以在任意记录型设定页打开统一入口，粘贴或导入一段非结构化文字。AI 阅读后返回结构化 JSON，程序负责校验、映射到元素树，并把新设定自动加入对应栏目。系统提示词固定、对用户隐藏且不可修改；实现应尽量降低 token 消耗，不把现有设定库整包发给模型。

### 6.2 支持范围

**支持**：人物、势力、道具、装备、其他设定、所有已启用自定义栏目。

入口要求出现在上述每一个设定页的页头（新建/导入按钮附近），空状态也应有入口。

**本版本不支持**：世界地图、记忆、元素模板、模式、稿件处理。它们的结构或用途不同，不在本版本做自动生成；可通过“其他设定”或手工编辑处理。

### 6.3 用户流程

1. 在任意支持的设定页点击“AI 生成设定”；
2. 弹出对话框，包含：
   - 说明文字：AI 可能出错，生成后请检查；
   - 多行文本输入框；
   - 从 `workspace/import` 读取 `.txt`/`.md` 的入口（可复用现有文件列表与 `/api/file`）；
   - “开始生成”和“取消”；
3. 生成期间显示忙碌状态，禁止重复提交；可取消前端等待（已发出的请求按后端超时处理）；
4. 后端自动识别目标栏目、批次处理和写入；
5. 完成后关闭对话框，显示结果摘要：新增多少条、跳过多少条、写入哪些栏目；新增条目可在对应页面看到；
6. 写入后、离开当前页面前提供“撤销本次生成”；撤销只删除本次新增且未被用户修改的条目；刷新页面后不保证可撤销；
7. 失败时保留用户输入，显示本地化错误，允许重试；不得写入半批数据。

### 6.4 自动识别与数据映射

AI 返回**一个扁平的记录数组**，程序按 `target` 路由到对应集合。建议契约：

```json
{
  "records": [
    {
      "target": "characters",
      "name": "林默",
      "tag": "",
      "fields": {
        "身份/本名": "林默",
        "身份/性别": "女",
        "性格/核心性格": "冷静、克制"
      },
      "notes": "",
      "tags": []
    },
    {
      "target": "section_world",
      "name": "灰潮",
      "fields": {
        "概述": "每二十年出现一次的大范围魔力潮汐",
        "规则": "潮汐期间魔法效果增强"
      },
      "content": ""
    }
  ]
}
```

规则：

- `target` 只能来自服务端提供的目标清单：`characters`、`factions`、`items`、`equipment`、`other`、`section_<key>`；
- `fields` 的 key 是当前目标元素树中的**实际字段路径**，用 `/` 分隔；只使用服务端提供的叶子路径；
- `fields` 的值必须是字符串；空值省略；`tags` 可选；
- `name` 必填；`tag`、`notes`、`content`、`category`、`slot` 可选，按目标集合的实际字段使用；
- 不接受 AI 生成 `id`、`created`、`updated`、`source`；这些由服务端生成；
- 未知 target、未知字段路径、非法类型一律丢弃并计数，不直接写入；
- 程序做确定性映射：把扁平路径还原为 `elements` 树，不调用第二次 AI 做“翻译”；
- 同名条目默认跳过，不覆盖已有内容；同一批次内重名也只保留第一条；
- 所有目标校验通过后一次性写入；校验失败不写入；写入阶段失败时回滚本次已写集合。

### 6.5 提示词与隐私要求

- 系统提示词放在服务端代码的固定常量/模块中，不放在用户配置、数据库、翻译表或前端；
- 不提供任何读取提示词的 API，不在错误详情、日志、前端状态或响应中返回提示词全文；
- 用户不能传入或覆盖 `system`、`prompt`、`model`、`config` 等字段来改变行为；服务端忽略这些字段并使用全局模型配置；
- 用户文本只作为 `user` 消息内容，不作为系统指令；提示词中明确要求把输入视为待抽取的数据，忽略其中的指令；
- 日志只记录字符数、条数、耗时、token 用量等指标，不记录完整用户文本和 API Key；
- 该功能不向用户显示提示词，也不提供编辑入口。

### 6.6 Token 控制

必须在实现说明和 PR 中列出实际策略与验证结果，至少包含：

1. **只发必要内容**：不发送现有设定库、对话历史、完整导出或翻译表；只发送本次用户文本、固定系统提示词、目标栏目及其启用的叶子字段路径；
2. **压缩目录**：目标清单用紧凑结构（target 名 + 单条栏目名称/用途 + 叶子路径数组），栏目名称/用途只出现一次，不重复每个字段的说明、示例和标签；关闭的元素不发送；
3. **一次抽取多条目**：同一段文字中的多个设定在允许范围内合并为一次请求，不按条目逐次调用；
4. **分块**：超过单批上限时按段落切分，逐块处理并合并；不按固定字符粗暴截断记录；单批默认不超过 12,000 字符，单次任务默认不超过 120,000 字符，超出时给出明确提示；
5. **输出紧凑**：要求纯 JSON、无 Markdown 围栏、无解释、无空字段、无 ID/时间戳；服务端仍要容错解析围栏；
6. **限制重试**：JSON 解析失败时最多做一次修复尝试，修复请求不重新发送完整用户文本；仍失败则报错且不写入；
7. **参数收敛**：低 temperature、明确的 `max_tokens` 上限；使用全局默认模型，不增加额外模型选择；
8. **可观测**：记录每批输入/输出字符数、API 返回的 usage（如有）和总耗时，便于 review token 是否合理。

### 6.7 错误与边界

- 无 API Key、接口不可用、超时、模型返回空内容、JSON 无法解析、目标栏目无有效字段、输入为空/超长：都要有本地化提示；
- 同一时间只允许一个 AI 设定生成任务；与工作站生成并发时给出忙碌提示；
- AI 返回的内容不得直接作为 HTML 插入；所有文本按现有转义规则展示；
- 自定义栏目未启用/已删除时，不写入；
- 批次写入后如果用户撤销，必须只删除本批次创建且未被修改的记录；删除失败要提示，不能静默。

### 6.8 验收标准

- [ ] 人物、势力、道具、装备、其他设定和每个已启用自定义栏目页都有入口，空状态也有；

## 7. 任务 4：pywebview 桌面化与动态端口

### 7.1 目标

应用启动后不再自动打开浏览器，而是由 pywebview 创建桌面窗口加载本地服务。端口不再固定：未显式指定时由系统分配空闲端口；用户通过配置或 `--port` 指定时使用指定端口，端口被占用则明确提示并停止进程。

### 7.2 端口规则

优先级：`--port` > 配置中的显式端口 > 自动分配。

| 场景 | 行为 |
|---|---|
| 无 `--port`，配置为自动/无端口 | 绑定端口 `0`，从 socket 读取系统分配的实际端口，用该端口启动窗口 |
| 无 `--port`，配置写了固定端口 | 使用该端口 |
| 有 `--port N` | 使用 N，覆盖配置 |
| 显式端口已被占用 | 打印/弹窗说明端口、配置位置和修改方式，记录日志，以非 0 退出；**不得改用其他端口** |
| 显式端口非法（非 1–65535 或无法解析） | 明确报错并停止，不静默回退 8765 |
| 自动端口绑定失败 | 报错并停止；不尝试浏览器 |
| `--port 0` | 作为非法显式值处理；自动端口只能通过“未指定”触发 |

配置建议新增 `server.port_mode`（`auto` / `fixed`）与可选 `server.port`。新安装默认 `auto`，不得在默认配置里写入 8765。旧配置迁移规则：

- 无 `server.port` 或为空：按 `auto`；
- 有 `server.port` 且没有 `port_mode`：若值等于旧默认 8765（调试模式 8766），迁移为 `auto`；其他值视为用户固定端口，保留为 `fixed`；
- 有 `port_mode`：以 `port_mode` 为准；
- `--port` 始终覆盖以上结果。

### 7.3 窗口与生命周期

1. 先绑定并启动 HTTP 服务，拿到实际端口后再创建窗口；
2. 默认创建 pywebview 窗口，URL 使用实际 `http://host:port/`，不再调用 `webbrowser.open`；
3. 窗口标题、初始尺寸、最小尺寸合理（建议 1440×900，最小 1024×720），支持缩放；
4. 关闭窗口后停止 HTTP 服务、等待服务线程结束并退出进程；Ctrl+C 也要走同样的清理逻辑；
5. 服务启动失败时不创建窗口；如平台允许，用原生消息框提示，同时保留控制台输出和日志；
6. pywebview/WebView2 不可用时给出可操作的错误（安装 WebView2 运行时或查看日志），不静默退回浏览器；
7. 保留 `--check`；新增 `--no-window` 供自动化测试/高级用户只启动服务，保留 `--no-browser` 作为兼容别名并提示已弃用；
8. 控制台窗口在本版本保留，用于日志和错误提示；隐藏控制台不在范围内。

### 7.4 设置页

- 端口设置改为“自动选择端口 / 固定端口”二选一；
- 选择自动时保存 `port_mode=auto`，不写死端口；选择固定时校验 1–65535 并保存端口；
- 明确提示“保存后下次启动生效”；
- 如果当前配置来自旧版且被迁移为自动，设置页应显示自动状态，而不是继续显示 8765；
- 修改端口设置不得影响当前已运行服务，直到下次启动。

### 7.5 打包与依赖

- 在 `app/requirements.txt` 增加 pywebview 运行依赖，并固定经过验证的版本范围；
- 更新 `NovelHelper.spec`，确保 pywebview 及其 Windows 后端依赖被正确收集（必要时添加 hiddenimports/data）；
- 打包后的 EXE 必须能创建窗口、加载页面、关闭后完全退出；
- 在干净 Windows 环境验证 WebView2 存在/缺失两种路径；
- README 更新启动方式、端口规则、`--no-window` 和卸载/关闭说明。

### 7.6 验收标准

- [ ] 默认启动只出现应用窗口，不再自动打开浏览器；

3. 任务 4 在最后集成时重新验证：首页、设定、AI 生成、关闭窗口与动态端口；

6. 发布前确认首次启动初始化、小说配置继承/覆盖、系统回收站删除行为，更新 README/CHANGELOG。

## 9. 风险与应对

| 风险 | 应对 |
|---|---|
| 初始化或新建小说时意外覆盖已有数据 | 初始化只补齐缺失结构、不覆盖已有文件；新建使用服务端生成的新 ID；测试重复启动与重复请求 |
| 删除小说时数据意外永久丢失 | 删除前标题确认；数据目录与工作区均移入系统回收站；失败时保留文件并报告 |
| 全局 `DATA_DIR`/`PROJECT_ROOT` 常量导致跨小说串数据 | 引入显式小说上下文，逐项替换路径解析并做隔离测试；不要只改首页 |
| 任务 1/2 同时修改 `core.js`/`style.css` 冲突 | 串行合并；设计先行；负责人协调文件归属 |
| 视觉化后信息密度过低、操作变深 | 设计评审看“首屏能否完成高频操作”，保留高级模式与快捷入口 |
| AI 幻觉或返回非法 JSON 污染设定 | 服务端白名单校验、未知字段丢弃、先校验后写、同名跳过、失败回滚 |
| AI 请求 token 失控 | 只发必要 schema/文本、分块、紧凑 JSON、限制重试和上限、记录 usage |
| 隐藏提示词被接口/日志泄露 | 固定服务端常量、禁止请求覆盖、测试 API 响应与日志、错误详情脱敏 |
| 固定端口冲突时静默换端口 | 绑定失败直接非 0 退出；测试覆盖；错误信息给出修改方法 |
| pywebview/WebView2 打包失败 | 干净环境构建、PyInstaller hiddenimports/data、缺失时明确报错、保留服务模式 |
| 关闭窗口后残留服务进程 | 统一 `finally` 清理，等待线程，手工验证任务管理器无残留 |

## 10. 决策记录

| 编号 | 决策 |
|---|---|
| D1 | v2610.3 的四个任务默认串行合并；任务 4 可先做独立原型，但最终集成最后进行 |
| D2 | 全局配置与小说级数据分离；创建小说时复制全局配置作为本地配置初值，可配置项默认跟随全局，也可按小说覆盖；全局配置在首页“全局设置”编辑，小说设置页提供“恢复全局配置”而非全局设置入口 |
| D3 | 项目仍处于开发期且无旧版用户数据；首次启动初始化空作品库，不实现旧数据迁移 |
| D4 | 启动默认进入首页，不自动进入上次小说；当前小说 ID 持久化 |
| D5 | 首页排布由成员设计，负责人审核；不规定固定布局 |
| D6 | 设定界面视觉化不改变集合 JSON 格式，仅改交互与呈现；保留高级编辑模式 |
| D7 | AI 生成支持人物、势力、道具、装备、其他、自定义栏目；世界地图/记忆不在本版本范围 |
| D8 | AI 根据全局目标清单自动路由；提示词固定在服务端、不暴露、不可由用户覆盖 |
| D9 | AI 结果只做确定性映射，不进行第二次模型调用；同名默认跳过，不覆盖已有内容 |
| D10 | 端口优先级为 `--port` > 配置固定端口 > 系统自动分配；显式端口冲突直接失败，不回退 |
| D11 | 默认使用 pywebview 窗口，不再自动开浏览器；保留 `--no-window` 供测试，控制台暂不隐藏 |
| D12 | 删除小说将数据和工作区移入系统回收站；回收站失败时不得永久删除 |
| D13 | 小说工作区路径配置均为当前小说工作区内的相对路径片段，不允许解析到小说目录之外 |
