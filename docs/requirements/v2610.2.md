## 1. 背景与目标

Novel-Helper 当前为本地端口访问的 Web 应用，代码集中在 `./app/novelhelper`，存在职责混杂、界面文案硬编码、无多语言能力等问题。本版本目标：

1. 对 `./app/novelhelper` 的 Python 业务代码做职责分离，形成边界清晰、对外仅暴露公共接口的软件包结构；
2. 建立可扩展的本地化基础设施，包括语言配置、翻译表、后端取词接口与前端翻译表注册机制；
3. 将现有硬编码界面文案迁移为 key→val 形式，至少支持简体中文与英文；
4. 增加首次进入语言选择，并在现有系统设置页中增加语言切换。

**非目标**：

- 不新增业务功能；
- 不改变现有数据存储路径与格式；
- 不改变对外 URL；
- 不引入重型前端框架；
- 不翻译日志、异常堆栈、调试信息与默认提示词；
- 不重构 `./app/novelhelper/web` 的前端架构。

**顺序原则**：先完成任务 1 稳定目录与接口边界，再新增本地化能力。若先做本地化，重构时需同时搬动新增代码，冲突与回归风险显著增大。本版本内三个任务严格串行，不允许并行修改 `./app/novelhelper`。

## 3. 任务 1：项目结构重构

### 3.1 目标

对 `./app/novelhelper` 的 Python 业务代码按职责拆分为多个软件包；包内实现细节不对外暴露，包间通过公共接口调用；产出接口文档。

### 3.2 范围与豁免

**在范围内**：`./app/novelhelper` 下的 Python 业务代码，按职责拆分（如 JSON 存储与处理、业务服务、路由/接口、工具等）。

**豁免（明确不动）**：

- 启动入口（如 `app/run.py`）、`app/__init__.py`；
- `app/novelhelper/__init__.py` 仅允许做公共 API re-export；
- `app/novelhelper/web/` 整体不动（HTML/CSS/JS 等前端资源，留给任务 2/3.1/3.2 处理）；
- 静态资源、模板、配置文件目录（除非为适配 Python import 路径必须调整，且需在 PR 说明）；
- 已职责单一且独立的模块可保留原位置。

**不改变**：对外 URL、JSON 存储路径与格式、配置项名称、前端资源引用路径、公共函数签名与返回结构。

### 3.3 目标结构（示意）

```
app/novelhelper/
  __init__.py          # 仅 re-export 公共 API
  core/                # 领域模型/核心逻辑
  storage/             # JSON 存储与处理
  services/            # 业务服务
  routes/ 或 api/      # 路由/接口层
  utils/               # 通用工具
  web/                 # 前端资源，本任务不动
```

最终结构以现状分析后的迁移计划为准，记录于 `docs/architecture.md`。

### 3.4 详细要求

1. **职责分离**：每个包单一职责，禁止循环依赖；跨包只依赖对方 `__init__.py` 暴露的公共 API。
2. **接口暴露**：包 `__init__.py` 用 `__all__` 声明公共 API 并 re-export；内部模块以 `_` 前缀标识私有；文档只列 `__all__` 内容。
3. **行为不变**：只搬移与重组，不优化、不改逻辑、不改文案、不改默认值。
4. **保留历史**：文件移动使用 `git mv`，禁止删除后新建。
5. **分批提交**：按包拆 PR 或至少按包拆 commit，每批可独立回滚、独立验证。
6. **最小冒烟回归**：新增 `scripts/smoke_test.py`，覆盖服务启动、首页 200、关键 API 200、JSON 读写往返、核心流程只读检查。重构前后均执行并记录结果。
7. **接口文档**：`docs/api/<package>.md`，内容与 `__all__`/docstring 一致；建议用 `pdoc` 或 `mkdocstrings` 生成，PR 附生成命令。

### 3.5 交付物

- 重构后代码与分批 PR 记录；
- `docs/architecture.md` 中的现状→目标映射、各包职责说明、豁免清单确认；
- `docs/api/*.md` 接口文档；
- `scripts/smoke_test.py` 及重构前后执行记录。

- [ ] 无循环依赖（提供 `pydeps` 或 import 检查结果）；

## 4. 任务 2：本地化基础

### 4.1 目标

在任务 1 稳定结构上新增本地化能力：后端语言配置、翻译表加载、取词接口、前端翻译表注册机制与校验；产出接口文档。

### 4.2 目录与文件

```
app/novelhelper/localization/          # 后端实现
app/novelhelper/web/i18n/              # 前端 i18n 运行时（注册、取词、data-i18n 绑定）
  i18n.js
app/resources/localization/
  languages.json                       # 语言清单与默认/回退配置
  zh-CN.yml
  en-US.yml
```

- 语言 ID 采用 BCP 47（`zh-CN`、`en-US`），文件名即语言 ID；
- 每语言一个 yml，新增语言不改已有文件；
- yml 使用 UTF-8（无 BOM），读取必须 `yaml.safe_load`；
- 前端运行时放在 `app/novelhelper/web/i18n/`，不改变后端包职责；具体文件名可按现有前端结构微调，需在文档中记录。

### 4.3 语言配置 `languages.json`

```json
{
  "default": "zh-CN",
  "fallback": "zh-CN",
  "languages": [
    { "id": "zh-CN", "name": "简体中文" },
    { "id": "en-US", "name": "English" }
  ]
}
```

- `name` 使用该语言自称，不随界面语言变化；
- 新增语言仅需加 JSON 条目与同名 yml，不改代码。

### 4.4 翻译表格式与 key 规范

```yaml
common:
  save: "保存"
  cancel: "取消"
settings:
  language: "语言"
  switch_success: "语言已切换为 {name}"
```

- key 使用小写字母、数字、下划线，层级用 `.` 表示（`settings.language`）；
- 动态内容一律使用 `{placeholder}` 整句翻译，禁止拼接句子片段；
- 中英 key 集合必须一致，以默认语言为基准做校验。

### 4.5 接口契约

**后端**：

- `t(key: str, **params) -> str`：按当前语言取值，支持 `{name}` 插值；缺失 key 走回退策略；
- `set_language(lang_id: str) -> None` / `get_language() -> str`；
- `get_translations(lang_id: str) -> dict`：返回整表，供 API 使用；
- 语言切换后无需重启进程，下次 `t()` 生效（缓存需失效）。

**前端翻译表注册机制**：

- 后端提供 `GET /api/i18n/<lang_id>`，返回 `{ "lang": "en-US", "messages": { ... } }`；
- 前端在页面初始化时拉取当前语言翻译表，并调用 `i18n.register(messages)` 注册到前端 i18n 运行时；
- 前端运行时至少提供 `register(messages)`、`t(key, params)`、`apply(root)`（扫描 `data-i18n` 并填充文本）；
- 页面静态文案使用 `data-i18n="key"`；JS 动态文案统一调用 `t()`；禁止在 JS 中硬编码界面文案；
- 动态插入的 DOM 需在插入后调用 `apply(container)`。

**回退策略**：

1. 请求语言不存在 → 使用 `fallback`；
2. 某 key 在当前语言缺失 → 使用 `fallback` 语言的值；
3. 回退语言也缺失 → 返回 key 本身，并记录 warning 日志（含语言与 key）。

### 4.6 校验与测试

- 启动时校验：`languages.json` 中每个 `id` 必须有同名 yml；`default`/`fallback` 必须在清单内；
- 测试校验：各语言 key 集合与默认语言一致，缺失/多余均报错；
- 后端单元测试覆盖：正常取值、插值、语言缺失回退、key 缺失回退、warning 记录、切换后生效；
- 前端运行时测试：注册、取词、`data-i18n` 填充、动态容器 `apply`；
- 打包验证：资源路径统一处理（开发环境与 `sys._MEIPASS`），打包后能加载语言文件与前端运行时。

### 4.7 交付物

- `app/novelhelper/localization/` 实现与测试；
- `app/novelhelper/web/i18n/` 前端运行时与最小示例页；
- `languages.json`、`zh-CN.yml`、`en-US.yml`（可先含少量 key 供验证）；
- `docs/localization.md`：后端接口签名、插值语法、回退策略、前端注册方式与 `data-i18n` 用法、新增语言 SOP；
- 打包配置调整说明。

### 4.8 验收标准

- [ ] 目录与文件符合 4.2，语言 ID 为 BCP 47；
- [ ] `languages.json` 含 `default`、`fallback`、`id`、`name`，前端语言列表可从此读取；
- [ ] 取词接口支持插值；缺失语言/key 按 4.5 回退并记 warning；
- [ ] `GET /api/i18n/<lang>` 可用，前端 `i18n.register()` 注册示例可运行；
- [ ] `data-i18n` 静态填充与动态取词均可用；
- [ ] 新增一门语言仅加 JSON 条目与 yml 即可生效，无需改代码；
- [ ] 启动校验与 key 一致性校验生效，异常有明确报错；
- [ ] 后端单元测试与前端运行时测试全部通过；

## 5. 任务 3.1：本地化应用

### 5.1 目标

将现有硬编码界面文案按任务 2 规范迁移为 key→val，至少覆盖中、英；默认提示词除外。

### 5.2 范围

- `./app/novelhelper`：Python 侧用户可见文案，包括接口返回、通知、面向用户的错误提示；
- `./app/novelhelper/web`：HTML 静态文案、JS 动态文案、按钮/菜单/弹窗/提示等；
- `./app/resources/localization`：补全翻译表。

### 5.3 要求

1. **文案盘点清单先行**：`docs/i18n-inventory.md` 列出位置（含 `web/` 下文件与行号）、原文、key、是否翻译；验收逐项打勾。
2. **不翻译**：日志、异常堆栈、调试信息、默认提示词。默认提示词在 UI 上以“示例/默认内容”标注，避免误解为漏翻。
3. **动态字符串**：使用整句 key 与占位符，禁止拼接句子片段。
4. **错误提示**：面向用户的错误必须本地化；优先“错误码 + 前端翻译”，若改造成本高，允许后端取词接口返回当前语言译文，需在文档记录。
5. **前端**：按任务 2 注册机制接入；静态文案用 `data-i18n`，JS 动态文案用取词接口；动态插入 DOM 后调用 `apply()`；JS 内不得残留硬编码界面文案。
6. **前端不重构**：只做文案替换与 i18n 接入，不调整前端架构、不换框架、不改交互逻辑。
7. **英文审校**：英文文案需经负责人终审，PR 中确认。

### 5.4 交付物

- 迁移后的 Python/HTML/JS 代码与中英对齐的翻译表；
- `docs/i18n-inventory.md` 完成版；
- 英文文案审校记录；
- 关键页面中英截图（含设置页与核心流程页）。

### 5.5 验收标准

- [ ] 动态插入的 DOM 文案能正确应用翻译（附验证说明）；
- [ ] 默认提示词保持原文，且有说明；
- [ ] 日志/异常未翻译；
- [ ] 动态文案均为整句 key 与占位符，无句子拼接；

## 6. 任务 3.2：首次语言选择与设置切换

### 6.1 目标

- 首次进入时选择语言，选择即实时反馈并保存；
- 在现有系统设置页中增加语言切换项。

### 6.2 范围

- `./app/novelhelper`：首次判定、配置读写、语言切换接口；
- `./app/novelhelper/web`：首次选择界面、设置页语言项；
- `./app/resources/localization`：如需补充界面文案。

### 6.3 要求

1. **首次判定**：以后端本地配置文件为准。配置中无语言字段即视为首次；已有配置视为非首次；配置缺失或损坏时按首次处理并记录日志。
2. **首次交互**：展示语言列表（来源 `languages.json`），点击某语言即保存并立即以该语言重新渲染，无需额外确认。
3. **设置页**：在现有设置页中新增语言切换项，复用现有布局与交互规范；切换后立即生效（本版本允许刷新当前页面）；正在进行的生成任务不受影响或给出提示。
4. **禁止硬编码语言列表**：新增语言不改代码即可出现在选择界面。
5. **前端不重构**：只新增或扩展语言相关 UI，不改设置页整体结构。

### 6.4 交付物

- 首次选择界面与设置页语言项；
- 配置读写逻辑与测试；
- 交互录屏或截图：首次选择、设置页切换生效、重启保留。

### 6.5 验收标准

- [ ] 清空配置后首次进入弹出语言选择，列表来自 JSON；
- [ ] 点击语言立即生效并保存，无需二次确认；
- [ ] 已有配置时不弹首次选择；
- [ ] 现有设置页中可切换语言，切换后界面立即以新语言呈现；
- [ ] 重启应用后语言保持；
- [ ] 新增语言仅改 JSON 与 yml 即可出现在选择界面；
- [ ] 配置损坏时按首次处理且有日志；
- [ ] 切换语言不影响进行中的任务（或有明确提示）；
- [ ] 未改变设置页整体结构与既有交互；
- [ ] 附交互录屏或截图。

## 8. 风险与应对

| 风险 | 应对 |
|---|---|
| 大规模重构引入隐性行为变更 | 先计划后执行，分批小 PR，冒烟回归，diff 重点审查 |
| 文件移动丢失 git 历史 | 强制 `git mv`，抽查 `git log --follow` |
| 误改 `web/` 前端资源 | 任务 1 豁免清单，验收提供 `git diff` 证明 |
| 本地化资源打包丢失 | 统一资源路径处理，打包验收必查 |
| 前端 i18n 注册与现有 JS 初始化顺序冲突 | 明确初始化顺序，动态 DOM 插入后调用 `apply()`，验收覆盖动态内容 |
| 英文变长导致 UI 溢出 | 任务 3.1 验收含英文截图检查 |
| key 遗漏或中英不一致 | 盘点清单，启动校验与测试校验 |
