# localization 公共 API

入口：`novelhelper.localization`。实现细节位于 `_runtime.py`，跨包不直接导入私有模块。运行机制见[运行流程](../localization/runtime-flow.md)，调用示例见[接入与预览](../localization/usage.md)，原有约束见[本地化规范](../localization.md)。

| `__all__` 接口 | 返回值与异常 |
|---|---|
| `t(key: str, **params) -> str` | 插值后的译文，缺失按 fallback/key 回退 |
| `set_language(lang_id: str) -> None` | 修改进程默认语言；未知 ID 回退并警告；不持久化 |
| `get_language() -> str` | 请求覆盖语言或进程默认语言 |
| `get_translations(lang_id: str) -> dict` | 合并 fallback 的扁平字典副本 |
| `get_languages() -> dict` | default/fallback/languages/current 配置副本 |
| `resolve_language(lang_id: str) -> str` | 有效 ID，或 fallback |
| `initialize(resource_dir: Path \| None = None) -> None` | 原子加载并重置到 default；无效资源抛 ValueError |
| `validate_translations() -> None` | 缺失/额外 key 或占位符不一致抛 ValueError |
| `language_context(lang_id: str)` | 返回上下文管理器，退出后还原请求语言 |

所有接口第一次使用时可触发资源初始化并抛 `ValueError`。语言标签由配置控制，翻译值支持扁平或嵌套 YAML。`initialize` 主要用于启动与测试，运行期间通常只调用 `set_language` 或请求上下文。

```python
from novelhelper.localization import t, set_language, language_context

set_language("zh-CN")
with language_context("en-US"):
    assert t("common.save") == "Save"
assert t("common.save") == "保存"
```

不修改既有 store/project/server 包的 `__all__`、函数签名或数据格式；这里只新增独立的 localization 包。

## HTTP 接口

| 请求 | 返回结构 / 行为 |
|---|---|
| `GET /api/i18n` | 配置副本，包含 default、fallback、languages、current、由 APP_VERSION 提供的 version，以及 `first_run`（配置中无 language 字段时为 true；配置损坏时按首次处理并备份/记日志） |
| `GET /api/i18n/<lang_id>` | `{"lang": "en-US", "messages": {"common.save": "Save"}}`；messages 为与 fallback 合并的扁平字典 |
| `POST /api/settings/language` | 请求体 `{"language": "en-US"}`；写入 `config.language` 并立即切换进程默认语言。返回 `{"ok": true, "language": "en-US", "current": "en-US"}`；未知语言按 fallback 落盘；空语言返回 400 |

未知语言返回实际的 fallback ID，不修改进程默认值。业务请求可携带 X-NovelHelper-Language，临时覆盖该请求语言；未提供时采用进程默认值。

语言切换不影响进行中的生成任务：请求语言在分发时已由 `language_context` 固定。持久化与首次判定实现位于 `server/_language.py`，损坏配置的备份（K2）与日志也在此处理。

用户错误使用后端译文返回，保留原 error/detail 结构与状态码；外部服务详情、异常类名和堆栈保留原文用于诊断。
