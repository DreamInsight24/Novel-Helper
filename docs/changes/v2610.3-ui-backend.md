# v2610.3 UI 工作版本：后端改动说明

日期：2026-10-29。分支：`dev/v2610.3-UI`。对比基线：`30c3443`。

本说明覆盖本次提交相对该基线的全部后端增量，不把之前已经提交的多小说基础设施重复列为本次新增。当前为开发工作版本，不代表 v2610.3 任务 2 已全部验收。

## 1. 对话历史与续写

涉及 `history.py`、`server/_api.py`、`server/_generation.py`。

- 历史列表保留尚未生成内容的对话，便于重新打开草稿。
- 新增 `POST /api/history/rename`，同步会话标题与历史索引，保留原轮次。
- 新增 `context_messages`：发送最近最多 8 轮完整 user/assistant 消息，合计最多 60,000 字符；超过预算不截断半轮，不重复发送历史设定库正文。
- 工作站生成及发送预览接入上述历史；稿件处理继续不携带写稿会话历史。
- 工作站生成成功后清空已发送的输入和对应对话草稿，保留输出、选择和会话指针。

原因：前端改为持续对话式工作站后，必须真正携带上下文，支持简洁的会话管理，并避免成功发送的文字仍滞留在输入框。

## 2. 详细输入与设定正文进入上下文

涉及 `context.py`、`history.py`。

- 支持 `setting_categories` 与 `record_selections`（按集合保存条目 ID 列表）。只处理启用的选择类型；人物、势力、道具、装备、记忆、其他及已声明自定义栏目均可独立选择。
- 不再把空的势力选择解释为整栏发送；新选择格式忽略旧的 current_state。旧请求格式仍保留兼容分支。
- 历史回显解析新选择格式，过滤失效 ID 并统计缺失项。
- 各种记录及人物背包引用的道具/装备统一渲染可选 summary/content；人物能够反向读出所属势力与身份。
- 仅当关系的两端均在本次详细选择中时，附加这条关系的名称、方向和备注，不自动带入其他条目的正文。

原因：配合“侧栏设定 + 更多设定 + 具体条目”的选择方式，以及轻量的名称/概述/正文编辑器，保证所填内容和实际发送内容一致。

补充说明与要求的旧值合并、移除当前状态输入框均由前端处理，没有删除旧历史字段。

## 3. 设定 JSON 导入导出兼容

涉及 `project/_imports.py`、`project/_exports.py`。

- 导入/合并/导出保留 summary（概述）与 content（正文）。
- 导入嵌套 JSON 时把 summary/content/notes 及其中文键当作独立字段，避免重复变成元素树节点。
- 势力成员输出兼容旧对象指针与成员 ID，并携带身份备注、去重。

原因：轻量设定编辑增加了自由正文和概述，导入导出必须能够往返，AI 上下文也不能漏掉这些内容。

## 4. 小说级统一关联数据

新增 `relations.py`；修改 `store/_paths.py`、`store/_defaults.py`、`store/_collections.py`、`store/_repository.py`、`server/_records.py`。

- 新增按小说隔离的 relations.json，沿用现有 `/api/collections/relations` 读写接口，并纳入集合枚举及备份。
- 单条关系保存 id、source/target（collection + id）、type、directed、note；支持单向、双向以及不同名称的多条关系。
- 校验真实端点、非空类型、禁止自身关联；双向边规范化后去重，兼容同 ID 出现在不同集合的情况。
- 首次读取时从已有 factions.members/member_roles 建立“人物 → 势力：隶属”关系，兼容旧对象指针。
- 统一关联数据作为新版编辑的依据；旧 members/member_roles 字段保留为兼容投影。直接保存旧势力数据也会同步成员关系，并尽量保留已有关系 ID。
- 保存记录/栏目/地图时清理失效关联；记录跨集合搬运及旧自动归类时重定向端点，防止关系丢失。
- 集合枚举包含所有已声明栏目，包括未在侧栏显示的栏目，避免隐藏栏目关联被误当作坏引用清除。

原因：任意条目关联任意条目需要统一、双端可读的存储；共享节点、闭环、布局、展开与实时拖线由前端绘图处理，后端只保存真实关系。

说明：每个 JSON 文件仍使用临时文件加替换写入，关系同步在同一进程锁内执行；这不是跨多个文件的数据库事务，也没有新增全图 JSON 导入导出协议。

## 5. 稿件导入至章节

涉及 `project/_outputs.py`、`project/__init__.py`、`server/_api.py`。

- 新增 `write_chapter` 与 `POST /api/chapters`，将当前正文原样写入当前小说产出目录的 TXT 文件，并返回更新后的章节列表。
- 不加入 AI 生成标题、时间或模式头；清理文件名中的路径分隔符、非法字符和 Windows 保留名称。
- 使用排他创建，重名自动加编号，避免覆盖既有章节；空白内容拒绝保存。

原因：支撑稿件工作区的“导入至章节”，区别于右上角将既有章节加入素材的“从章节导入”。

素材、文件夹和正文草稿继续使用小说级 state.textPanel 及既有集合保存接口；这部分没有新增后端专用接口。

## 6. 默认栏目与本地化初始化

涉及 `store/_defaults.py`、`store/_localized.py`。

- 新建小说的自定义栏目默认只生成“世界设定”，不再预铺物种、魔法、历史、经济等多栏；旧小说已有栏目不自动搬运或删除。
- 增补“世界设定”的初始化本地化映射，调整相应默认值测试。

原因：让栏目按需显示、管理页统一配置，减少初始侧栏与表单负担。

## 7. 测试、模拟数据与没有变化的部分

- `app/selftest.py` 补充自由正文往返、详细选择、历史续写与预算、重命名、章节导入及重名保护检查。
- `scripts/test_relations.py` 使用临时小说验证迁移、去重、旧成员投影、引用校验、选择上下文、删除清理、小说隔离及 HTTP 搬运。
- `scripts/seed_relation_demo.py` 可向当前活动小说添加带“【示例】”标记的演示条目和关系；仅提交生成脚本，不提交真实小说目录。
- 原有后端 AI 记忆压缩流程没有重做；本次记忆库空白修复只补齐前端页面状态。
- 没有修改提供商协议、模型调用底层、依赖、固定端口或桌面启动方式。
